## 3. 目标设计：给每档一张「策略表」

新增一张 `MODE_STRATEGY`，让推荐函数真正认识档位。

| | 减脂档 jianzhi | 维持档 weichi | 增肌档 zengji |
|---|---|---|---|
| **一句话** | 优先压热量/脂肪/钠 | 优先六项全绿 | 优先补蛋白+碳水 |
| 加权指标（加分更多） | kcal, fat, sodium | 无（追求均衡） | protein, carb |
| 惩罚偏科 | 中 | **高**（要全绿） | 低 |
| 补短板允许热量上限 | 120 kcal | 200 kcal | 400 kcal |
| 硬约束 | 蛋白不得低于目标 90%；**不推高糖甜品/含糖饮料** | 总分不得下降 | 脂肪/钠不得由绿变红；补短板须含高蛋白项 |

**硬约束的解释**（务必实现，这是「定制」的可信度来源）：
- 减脂档不能为了压热量把蛋白砍到不及格——那是「减肌」不是「减脂」。
- 减脂档不能推荐高糖甜品（新地 / 圆筒冰淇淋 / 麦旋风 / 派）——
  实测当前代码就会推「新地」，这是最刺眼的语义错误。
- 增肌档不能为了补蛋白把钠吃超标。

**预期效果**：同一份餐盘，三档给出不同的替换项 / 补足项。
例如同样是「巨无霸+薯条+可乐」：
- 减脂档可能推「薯条 → 苹果片」（压热量）；
- 增肌档可能不换薯条，而是**补一份鸡胸/牛奶**（补蛋白）；
- 维持档优先把红灯项逐个修绿。

## 7. 务必避开的坑（前车之鉴）

1. **`overflow-x:hidden` 只是藏起滚动条，不等于内容不溢出。**
   判据用 `scrollWidth > clientWidth`，别只看有没有滚动条。
2. **改 CSS 媒体查询要放到 `<style>` 末尾** —— 同等特异性下**后写的赢**。
   放中间会被后面的基础规则覆盖。
3. **不用 `scrollIntoView`** —— 它会连带滚动遮罩后面的页面。
   手动算 `scrollTop` / `scrollLeft`。
4. **截图/探测用自研 CDP 脚本**：本机的 `headless-scroll-screenshot` 驱动
   `cdp_shot.py` 加 `--steps` 会卡死（空输出 + SIGTERM，换端口也无效）。
   可靠做法是自己写 ~120 行 stdlib 脚本直连 CDP：
   `--headless=new --remote-debugging-port=<空闲端口>` →
   读 `/json/list` 拿 `webSocketDebuggerUrl` → 手写 WebSocket 帧 →
   `Page.navigate` / `Runtime.evaluate` / `Page.captureScreenshot`。
   详见技能 `headless-scroll-screenshot` 的 Known pitfalls。
5. **别用 `rm -rf` 删临时目录**：文件多时会被 safe-delete 守卫拦截，
   且因为是 `&&` 链，**后续命令全被跳过、日志都不生成**，极难排查。
   要删就单独一条命令。
6. **元素选择器先 grep 确认**：是 `#addplus`（id）不是 `.addplus`（class）。
7. 提交前看 `git diff --stat`，出现 `Bin xxx -> 0 bytes` 说明**误删了二进制素材**，
   用 `git checkout -- <path>` 找回。
